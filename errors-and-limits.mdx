---
title: "Erros e limites"
description: "Códigos HTTP, formatos de erro e comportamento de repetição."
---

As respostas de erro usam JSON com `message` e `statusCode`. Erros de validação podem retornar uma lista em `message`.

| HTTP | Significado |
| --- | --- |
| `400` | Corpo inválido, valor fora do limite, referência reutilizada com outros dados ou chave Pix inválida. |
| `401` | API key ausente, inválida ou revogada; código de transferência inválido ou expirado. |
| `403` | A key não tem permissão para a rota. |
| `404` | Operação não encontrada na sua conta. |
| `429` | Limite temporário de requisições. |
| `503` | Serviço de pagamentos momentaneamente indisponível. |

Limites atuais: **120 chamadas/minuto por key**, **10 criações de cobrança/minuto por conta**, **10 criações de checkout de cartão/15 minutos por conta**, **30 envios automáticos/hora por conta**, **3 preparações pelo site/hora por conta**, **20 tentativas de confirmação de rascunhos legados a cada 10 minutos**, **30 criações de negócio/hora**, **30 exclusões de negócio/hora** e **60 renomeações de negócio/hora**. Uma conta mantém entre **1 e 10 negócios incluindo a principal**. O código do site e de rascunhos legados permite até cinco erros e expira em 10 minutos. Novos envios por API key não usam esse código.

Ao receber uma resposta incerta ou timeout após criar uma cobrança, repita **a mesma requisição com o mesmo `requestKey`**. Para cartão, a mesma referência retorna a operação sem repetir um checkout incerto; para transferências, consulte o ID antes de qualquer nova ação. Nunca troque o UUID para contornar um resultado incerto.
